The READ-COMMITTED winner-skew rollback remains intact because producer classics still run before binding reconciliation; a winner-B collision still aborts Tx2. `confirmAssertion` has no callers, though its new binding no-op deserves a real-Postgres regression test and its “INSERT a NEW assertion” documentation should be updated.

2. **NOT MERGE-SAFE as written.** The reader is the right conceptual layer; manufacturing an `object_content_snapshots` row is wrong because that subsystem serializes mutable `objects.data` as `application/json`, applies redaction, and keys it by claimant policy—it does not snapshot authored file bytes ([object-content-snapshot.ts](<lane-worktree>/src/lib/artifacts/object-content-snapshot.ts:17)). However, the proposed direct-read exception is based on a mutable, forgeable JSON field. A claimed pack-typed typed-DATA row with an existing direct blob representation can be changed through `objects_update` to add `artifactType:"file"`; the same representation that the ratified test currently rejects will then serve without a snapshot, fingerprint, or redaction check. Use an immutable, writer-owned provenance discriminator—ideally DB-enforced, or at minimum correlated with the creation audit/representation—not this field alone.

3. **NOT MERGE-SAFE.** Repository literals are only stamped explicitly by `artifact-creation.ts`, but that does not make the value non-forgeable. `objects_save` persists classifier-normalized caller data, while `objects_update` merges caller fields into existing data ([handlers.ts](<lane-worktree>/packages/objects/src/mcp/handlers.ts:1438)). Self-owned artifact types without inline schemas explicitly receive permissive `z.record(...)` validation ([register-artifact-extensions.ts](<lane-worktree>/packages/objects/src/integration/register-artifact-extensions.ts:296)); JSON Schemas may also allow additional properties. A non-`isArtifact` DATA_TYPE row cannot pass the new type predicate, but a claimed pack-typed typed-DATA row—the exact class protected by the unchanged #1785 test—can carry this field. Source-code uniqueness is not a security boundary.

4. **MERGE-SAFE.** Changing the ratified test is legitimate. The real invariant is “a classic never displaces a binding,” not “the attempt must abort on a unique-index violation.” The revised test proves the stronger intended contract: clean precedence no-op, binding survives, and zero competing classics exist. Raw uniqueness remains independently covered by `sa_active_unique_idx` tests for competing classics and active bindings.

5. **NOT MERGE-SAFE; material context paths are missing.** `context-resolver.ts` still labels every binding-bearing row `is_claimed` and therefore selects only a capture-time snapshot plus its binding assertion ([context-resolver.ts](<lane-worktree>/src/lib/artifacts/context-resolver.ts:319)). Worse, capture will snapshot the file envelope’s metadata JSON rather than use the authored blob; if snapshot policy/redaction refuses it, the file disappears entirely. The fix needs one trusted file-provenance rule across serve, snapshot-candidate capture, context resolution, and both finalizer queries. Add an end-to-end produce→context-resolve→finalize test proving the original authored revision is selected with the binding assertion, plus a claimed pack-typed typed-DATA forgery control. The current DATA_TYPE isolation control is not `isArtifact`, so it does not exercise the vulnerable new OR arm.
