# Isolated design-suite partition trials

The normal design suite remains one serial worker. An explicit `CINATRA_DESIGN_PARTITION=1/2` or `2/2` enables Playwright sharding with one worker per partition. This is an opt-in validation facility; CI does not enable it until a controlled run demonstrates isolation and lower time to a complete passing result.

Each partition needs its own prebuilt application process and fresh PostgreSQL database. A schema alone is insufficient because provisioning also writes public authentication tables. With `CINATRA_DESIGN_PARTITION_RUN_ID=trial-a`, the required database names are `cinatra_design_trial_a_p1` and `cinatra_design_trial_a_p2`. Redis URLs select database `/1` and `/2` respectively on a dedicated disposable trial Redis instance. At provisioning, set its database-0 key `cinatra:design-partition:owner` to the trial run id; the test preflight only reads this reservation and refuses an absent or different owner. Never create that binding on a shared instance. Never reuse an active lane's database or flush a shared Redis database.

Set the same partition environment on the server and its test process: partition index, trial run id, `CINATRA_DESIGN_HEAD_SHA` (the exact tested commit), PostgreSQL URL, Redis URL, and `CINATRA_DESIGN_PARTITION_BASE_PORT`. The server ports are the base port and base port plus one. The seed capability remains required and must match the respective server and test process. The fixture namespace is derived as `trial-a-p1` or `trial-a-p2`; the seed route refuses writes for another partition's namespace. This also isolates fixed fixture identifiers through the independent databases. Managed boots refuse server reuse. An external server is probed through the capability-protected seed identity endpoint before any test project starts; its head, namespace, database, port and Redis address must match the test process.

Set `CINATRA_DESIGN_ARTIFACT_ROOT` to an absolute private directory outside the product checkout. Test results and reports go into separate run-id subdirectories. Both partitions must consume the identical frozen selection plan and run `node scripts/ci/design-select.mjs --run --plan <plan-file>`. Neither partition may choose its own diff. A complete result requires both partitions to succeed at the same head and design pin.

Before a timing trial, run the ordinary suite and both partition configurations with Playwright `--list --reporter=json`. Compare test identifiers and project names: the two partitions must be disjoint and their union must equal the ordinary selected inventory. Then record whole-run elapsed time, setup time, peak memory, and both result summaries privately. Count failed/cancelled attempts in the comparison. Keep the serial default if there is no demonstrated improvement or if both application processes exceed admitted host capacity. CI stops at the first concluded design failure; retries retain their existing one-retry budget.
